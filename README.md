# RoomVision AI

RoomVision AI turns a photo of your room into a professionally redesigned interior. You upload a photo, choose a room type, style, colour palette and budget, and the app creates a photorealistic redesign with Google Gemini. It also detects the furniture in your photo with YOLO11n computer vision. You can compare the original and the redesign with a before/after slider and download the result.

## Features

- Drag-and-drop photo upload (JPG, PNG, WEBP, up to 10 MB) with preview, replace and remove
- Furniture detection with Ultralytics YOLO11n (beds, chairs, couches, tables, TVs, plants, kitchen appliances and more)
- 6 room types, 9 design styles, 7 colour palettes (including a custom one) and 4 budget levels
- Free-text extra instructions and a "keep my furniture layout" switch
- Photorealistic redesign generated by Google Gemini from your own photo
- Before/after comparison slider, design details and detection results
- Download button for the redesigned image
- Honest error handling: if the AI returns no image, you see a clear message, never a fake result

## Technology stack

| Part | Technology |
| --- | --- |
| Frontend | React 18, Vite, JavaScript, CSS, Lucide React icons |
| Backend | Python 3.11, FastAPI, Uvicorn, python-multipart, python-dotenv |
| AI image generation | Google GenAI SDK (`google-genai`) with a Gemini image-output model |
| Computer vision | Ultralytics YOLO11n (pretrained) on CPU PyTorch |
| Hosting | GitHub, Render Static Site (frontend), Render Web Service (backend) |

## Architecture

```
Browser (React)  --HTTPS-->  FastAPI backend  --->  YOLO11n (detect furniture)
                                   |
                                   +------------->  Gemini (generate redesign)
                                   |
                                   +--> saves image in backend/generated/ and returns its URL
```

1. The browser sends the photo and the choices to `POST /generate-redesign`.
2. The backend validates the image, runs YOLO (optional, non-fatal), builds a detailed design prompt and sends the photo and prompt to Gemini.
3. Gemini returns an image. The backend checks it is a real image, saves it under a random UUID name and returns its URL and the design details.
4. The browser shows the original and the redesign in the comparison slider.

The API key lives only on the backend. The frontend never sees it.

## Environment variables

### Backend (set in `backend/.env` locally, or in the Render dashboard)

| Name | Required | Example | What it does |
| --- | --- | --- | --- |
| `GEMINI_API_KEY` | Yes | `AIza...` | Your key from https://aistudio.google.com/apikey |
| `GEMINI_MODEL` | No | `gemini-2.5-flash-image` | A Gemini model that can output images. Change it here if Google renames or replaces models. |
| `ENVIRONMENT` | No | `production` | Use `production` on Render. Locally the default `development` also allows `http://localhost:5173`. |
| `FRONTEND_URL` | Yes on Render | `https://roomvision-ai.onrender.com` | Your deployed frontend address. Comma-separate several. No trailing slash. |
| `PYTHON_VERSION` | Yes on Render | `3.11.9` | Makes Render use a Python version PyTorch supports. |
| `ENABLE_DETECTION` | No | `true` | Set to `false` if the server runs out of memory. Designs still work, without furniture detection. |
| `MAX_UPLOAD_MB`, `GEMINI_TIMEOUT_SECONDS`, `YOLO_CONFIDENCE`, `GENERATED_TTL_MINUTES`, `MAX_CONCURRENT_GENERATIONS`, `PRELOAD_DETECTOR` | No | | Optional tuning. See `backend/config.py`. |

### Frontend

| Name | Required | Example |
| --- | --- | --- |
| `VITE_API_BASE_URL` | Yes | `https://roomvision-api.onrender.com` (no trailing slash) |

`VITE_` values are built into the website and visible to everyone. Never put secrets in them.

## Local development (optional)

You do not need this to deploy. It is useful if you want to test on your own computer first.

Backend (Python 3.11 recommended):
```
cd backend
python -m venv .venv
.venv\Scripts\activate            (Mac/Linux: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env            (Mac/Linux: cp .env.example .env)   then put your Gemini key in .env
uvicorn main:app --reload --port 8000
```
Check `http://localhost:8000/health` and the interactive docs at `http://localhost:8000/docs`.

Frontend (Node.js LTS):
```
cd frontend
copy .env.example .env.local      (Mac/Linux: cp .env.example .env.local)
npm install
npm run dev
```
Open `http://localhost:5173`.

## API documentation

All errors return JSON like `{"detail": "A readable message"}` with a suitable HTTP status (400, 413, 415, 422, 429, 500, 502, 503, 504).

### `GET /`
Returns the API name, version and a list of endpoints.

### `GET /health`
```json
{ "status": "ok", "service": "RoomVision AI API", "version": "1.0.0", "environment": "production",
  "gemini_configured": true, "gemini_model": "gemini-2.5-flash-image",
  "detection_enabled": true, "detector_loaded": false }
```

### `POST /analyze-room`
Form data: `file` (image). Returns:
```json
{ "success": true, "count": 2, "image_width": 1536, "image_height": 1024,
  "objects": [ { "label": "couch", "confidence": 0.91, "bbox": { "x1": 10.0, "y1": 20.0, "x2": 400.0, "y2": 300.0 } } ] }
```
Returns 503 if detection is unavailable.

### `POST /generate-redesign`
Form data:

| Field | Values |
| --- | --- |
| `file` | image (JPG, PNG, WEBP, max 10 MB) |
| `room_type` | `bedroom`, `living_room`, `kitchen`, `dining_room`, `bathroom`, `other` |
| `design_style` | `modern`, `minimalist`, `scandinavian`, `bohemian`, `industrial`, `contemporary`, `luxury`, `japandi`, `traditional` |
| `color_palette` | `warm_neutrals`, `cool_neutrals`, `earthy_tones`, `monochrome`, `pastel`, `bold_colors`, `custom` |
| `custom_palette` | text, required when `color_palette` is `custom` (max 120 characters) |
| `budget` | `low`, `moderate`, `premium`, `luxury` |
| `additional_instructions` | optional text (max 800 characters) |
| `preserve_layout` | `true` or `false` (default `true`) |

Returns:
```json
{ "success": true, "image_url": "/generated/<uuid>.png", "download_url": "/download/<uuid>.png", "filename": "<uuid>.png",
  "metadata": { "design_style": "...", "room_type": "...", "color_palette": "...", "custom_palette": "", "budget": "...",
                "additional_instructions": "", "preserve_layout": true, "model": "gemini-2.5-flash-image" },
  "detection": { "available": true, "count": 2, "objects": [ ... ], "image_width": 1536, "image_height": 1024 },
  "ai_notes": "" }
```
`image_url` is relative to the backend address. The frontend adds the backend address in front.

### `GET /download/{filename}`
Downloads a generated image as a file. Returns 404 once the image has expired.

## Deployment: GitHub and Render, step by step

You need three free accounts: GitHub, Render and Google AI Studio (for the Gemini key). No commands are needed on your computer.

### Step 1. Get a Gemini API key
1. Go to https://aistudio.google.com/apikey and sign in with a Google account.
2. Create an API key and copy it somewhere private. Never paste it into GitHub, a chat or a screenshot.
3. Image generation may require billing to be enabled on your Google project. If generation later fails with a quota or permission message, check this first.

### Step 2. Put the files on GitHub (no commands)
1. On github.com click **New repository**. Give it a name such as `roomvision-ai`. Leave "Add a README" and "Add .gitignore" **unticked**. Click **Create repository**.
2. Unzip `roomvision-ai.zip` on your computer and open the `roomvision-ai` folder.
3. **Mac users:** press `Cmd + Shift + .` in Finder to show hidden files, because `.python-version` and `.gitignore` start with a dot.
4. On your new repository page, click **uploading an existing file** (or **Add file > Upload files**).
5. Select everything **inside** the `roomvision-ai` folder (`backend`, `frontend`, `README.md`, `.gitignore`, `.python-version`) and drag it into the browser window. Do not drag the outer `roomvision-ai` folder itself, or Render will not find `backend` and `frontend` at the top level.
6. Wait for the upload to finish, then click **Commit changes**.
7. Check that the repository's front page shows `backend`, `frontend` and `README.md`.

(If you prefer git commands: `git init`, `git add .`, `git commit -m "Initial commit"`, `git branch -M main`, `git remote add origin <your repo URL>`, `git push -u origin main`.)

### Step 3. Deploy the backend on Render
1. Sign up at render.com with your GitHub account.
2. Click **+ New** then **Web Service**, and pick your repository.
3. Fill in the form:

| Field | Value |
| --- | --- |
| Name | `roomvision-api` (or any name) |
| Language | Python 3 |
| Branch | `main` |
| Root Directory | `backend` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn main:app --host 0.0.0.0 --port $PORT` |
| Instance Type | Free |

4. Under **Environment Variables** add:
   - `PYTHON_VERSION` = `3.11.9`
   - `GEMINI_API_KEY` = your key
   - `GEMINI_MODEL` = `gemini-2.5-flash-image`
   - `ENVIRONMENT` = `production`
5. Open **Advanced** and set **Health Check Path** to `/health`.
6. Click **Create Web Service**. The first build takes several minutes because PyTorch is large.
7. When it shows **Live**, copy the service address (it looks like `https://roomvision-api.onrender.com`) and open `<that address>/health` in your browser. You should see `"status": "ok"`.

### Step 4. Deploy the frontend on Render
1. Click **+ New** then **Static Site**, and pick the same repository.
2. Fill in the form:

| Field | Value |
| --- | --- |
| Name | `roomvision-ai` (or any name) |
| Branch | `main` |
| Root Directory | `frontend` |
| Build Command | `npm install && npm run build` |
| Publish Directory | `dist` |

3. Add the environment variable `VITE_API_BASE_URL` = your backend address from Step 3, with **no slash at the end**.
4. Click **Create Static Site** and wait for it to go live. Copy its address (for example `https://roomvision-ai.onrender.com`).

### Step 5. Allow the frontend to talk to the backend (CORS)
1. Go back to your **backend** service in Render, open **Environment**.
2. Add `FRONTEND_URL` = the frontend address from Step 4 (starts with `https://`, no slash at the end).
3. Save. Render redeploys the backend automatically.

### Step 6. Try it
Open your frontend address, click **Design my room**, upload a photo and press **Generate redesign**. Share the frontend address for demos.

If you change `VITE_API_BASE_URL` later, trigger a new frontend deploy (**Manual Deploy**), because the value is built into the site.

### Updating the site later
Edit or upload changed files on GitHub. Render redeploys automatically on every commit to `main`.

## Free-tier limitations and storage

- **Sleeping:** Render free web services spin down after 15 minutes without traffic. The first request afterwards can take about a minute. The site pings the server on load to wake it early, and tells you when it is still waking up. Open the site a minute before a live demo.
- **Memory:** a free instance has 512 MB of RAM. PyTorch and YOLO are heavy, so the backend may run out of memory. If the service restarts during a request, set `ENABLE_DETECTION` to `false`. Designs still generate, just without furniture detection. A paid instance with 2 GB removes this problem.
- **Temporary files:** Render's free filesystem is wiped on every restart, redeploy and spin-down. Generated images are therefore temporary (the app also deletes them after 60 minutes). The results page tells users to download their design.
- **Making images permanent:** save each generated image to object storage right after generation, and return that URL. Common options: Cloudinary, Supabase Storage, AWS S3 or Google Cloud Storage (all have free tiers), or a paid Render Persistent Disk. This needs a small change in `backend/main.py`.
- **Gemini limits:** image generation is subject to Google's quotas, pricing and model availability. Models are renamed and retired over time, so check Google's documentation if you see a "model not found" message and update `GEMINI_MODEL`.
- **AI results vary:** the model can alter small details, and it may occasionally refuse a photo or return no image. The app reports this instead of pretending it worked.
- **No accounts or history:** designs are not saved per user.
- **Landing page art:** the hero picture is a drawn illustration, not an AI result. Replace it with your own generated examples if you like.

## Troubleshooting

| Problem | What to try |
| --- | --- |
| Backend build fails while installing `torch` | Make sure `PYTHON_VERSION` is `3.11.9` in the backend's Environment settings, then redeploy. |
| Backend restarts or "Out of memory" in the logs | Set `ENABLE_DETECTION=false`, or use a larger instance. |
| Logs mention `libGL.so.1` when detecting | Change the Build Command to `pip install -r requirements.txt && pip uninstall -y opencv-python && pip install opencv-python-headless`. |
| Browser shows a CORS or "could not reach the server" error | Check `FRONTEND_URL` exactly matches the frontend address (https, no trailing slash) and that the backend has redeployed. |
| Site says it is not connected to its server | `VITE_API_BASE_URL` is missing. Add it and redeploy the frontend. |
| "model does not support image output" or "model not found" | Set `GEMINI_MODEL` to a current Gemini model that can output images. |
| Quota, permission or invalid key messages | Check the key, billing and quotas in Google AI Studio. |
| First request is very slow | The free server was asleep. Wait a minute and try again. |
